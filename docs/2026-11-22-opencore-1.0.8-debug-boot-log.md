## 1. 为什么原来抓不到日志

| 项 | 原值 | 问题 |
|---|---|---|
| `Misc > Debug > Target` | `3`（0x01+0x02） | 只写 OpenCore 变量 + 屏显，**0x40（写文件）没开**，ESP 上永远不会有 `opencore-*.txt` |
| `Misc > Debug > DisplayLevel` | `2147483650`（0x80000002） | 只有 `DEBUG_ERROR`，屏显几乎空白 |
| `Misc > Debug > AppleDebug`/`ApplePanic` | `false` | boot.efi 阶段与 panic 都不落盘 |
| `boot-args` | 无 `-v` | 进度条代替了内核文本，卡在哪一行看不见 |
| OpenCore 构建 | RELEASE（`OpenCore.efi` 630,784 B） | 即使开 `Target` 也只有 ERROR/WARN，没有 INFO/VERBOSE |

## 2. 现在的调试态（已在 `config.plist` 里）

| 键 | 值 | 含义 |
|---|---|---|
| `Misc > Debug > Target` | `67` = 0x43 | 0x01 日志 + 0x02 屏显 + 0x40 **写文件**（文件落 ESP 根目录 `opencore-YYYY-MM-DD-HH-MM-SS.txt`） |
| `Misc > Debug > DisplayLevel` | `2147483714` = 0x80000042 | 0x80000000 ERROR + 0x00000040 INFO + 0x00000002 WARN |
| `Misc > Debug > AppleDebug` | `true` | boot.efi 阶段日志也落盘 |
| `Misc > Debug > ApplePanic` | `true` | panic 写盘（配合 `keepsyms=1` 才有符号） |
| `Misc > Debug > LogModules` | `*` | 1.0.8 新增键，默认全模块 |
| `NVRAM > boot-args` | `ipc_control_port_options=0 ctrsmt=full darkwake=0 e1000=0 -v keepsyms=1 debug=0x100` | `-v` 内核 verbose；`debug=0x100` 让 panic 时继续往控制台打印 |

`Target` 位表（官方 `Configuration.pdf` / [Dortania 调试页](https://dortania.github.io/OpenCore-Install-Guide/troubleshooting/debug.html)）：`0x01` 日志、`0x02` 屏显、`0x04` Data Hub、`0x08` 串口、`0x10` UEFI 变量、`0x20` 非易失变量、`0x40` 写文件。

## 3. 换了什么二进制（OpenCore 1.0.8 DEBUG）

来源：`https://github.com/acidanthera/OpenCorePkg/releases/download/1.0.8/OpenCore-1.0.8-DEBUG.zip`（包内 `X64\` 目录，x86_64 机器用这一套）。

| 路径 | 旧大小 | 新大小 | 新 SHA256（前 16 位） |
|---|---|---|---|
| `OpenCore.efi` | 630,784 | 868,352 | `11BA0B763D765FB8` |
| `Drivers/OpenRuntime.efi` | 24,576 | 36,864 | `CF2DF818F7510CA1` |
| `Drivers/OpenCanopy.efi` | 114,688 | 151,552 | `59F4089B2DBDA897` |
| `Drivers/ResetNvramEntry.efi` | 45,056 | 57,344 | `E89433174BE279F1` |
| `esp/BOOT/BOOTx64.efi`（新增，仓库内暂存） | — | 53,248 | `7B26E33BFD84FBC5` |

**没有动**的两个驱动：

- `Drivers/apfs_aligned.efi`（718,340 B）——自己改过的 APFS 驱动，官方 DEBUG 包里没有对应物，保留原文件。OC 更新后它若与新内核/新固件不合，日志里会指名报错。
- `Drivers/HfsPlus.efi`（37,892 B）——Apple 原版，不随 OC 版本变化。

`esp/BOOT/BOOTx64.efi` 之所以单独放 `esp/`，是因为仓库根目录对应的是 ESP 的 `EFI\OC`，而 BOOTx64 在 `EFI\BOOT`。`esp/` 目录按 `EFI\` 的结构镜像，部署时单独 robocopy 一次（§5）。

## 4. config.plist 迁移到 1.0.8 schema

旧 config 是更早版本的 schema。用 1.0.8 官方 `ocvalidate` 校验，原文件报 **34 个问题**；迁移后报 **No issues found**。

迁移原则：**只补缺失键（一律取 1.0.8 默认值）、只删已废除键、不动任何既有取值**。事后逐键语义对比确认 `CHANGED = 0`。

新增 29 项：

| 分组 | 键 |
|---|---|
| `Booter > Quirks` | `ClearTaskSwitchBit`、`FixupAppleEfiImages` |
| `Kernel > Quirks` | `CustomPciSerialDevice`、`DisableIoMapperMapping`、`ForceAquantiaEthernet` |
| `Misc > Boot` | `HibernateSkipsPicker`、`InstanceIdentifier` |
| `Misc > Debug` | `LogModules`（`*`） |
| `Misc > Serial` | 整节新增：`Init=false`、`Override=false`（`Init` 就是原 `Debug > SerialInit` 搬过去的位置） |
| `UEFI > AppleInput` | `PointerDwellClickTimeout`、`PointerDwellDoubleClickTimeout`、`PointerDwellRadius` |
| `UEFI > Drivers[*]` | 每个驱动补 `HideVerbose=false`、`LoadEarly=false` |
| `UEFI > Output` | `ConsoleFont`、`GopBurstMode=false`、`InitialMode=Auto` |
| `UEFI > ProtocolOverrides` | `PciIo=false` |
| `UEFI > Quirks` | `ResizeUsePciRbIo=false`、`ShimRetainProtocol=false` |
| `UEFI` | `Unload`（空数组） |

删除 4 项（1.0.8 已无这些键，原值全是 `false`，无行为损失）：

- `Misc > Debug > SerialInit` → 搬到 `Misc > Serial > Init`
- `Misc > Security > AllowNvramReset`
- `Misc > Security > AllowToggleSip`
- `NVRAM > LegacyEnable`

`LoadEarly` 全部设 `false` 是硬要求：`ocvalidate` 会对 `apfs_aligned.efi`/`HfsPlus.efi`/`OpenCanopy.efi`/`ResetNvramEntry.efi` 报「must have LoadEarly set to FALSE」，`OpenRuntime.efi` 在没启用 `OpenVariableRuntimeDxe.efi` 时也必须是 `false`。

## 5. 部署（提升权限的 PowerShell）

```powershell
# 1) 定位 ESP
$list = mountvol | Out-String
$m = [regex]::Match($list, 'The EFI System Partition is mounted at ([A-Z]):')
if ($m.Success) { $letter = $m.Groups[1].Value }
else { cmd /c 'mountvol D: /S' | Out-Null; $letter = 'D' }
$esp = "${letter}:\EFI\OC"

# 2) 先备份 ESP 上现有的 BOOTx64.efi（仓库里没有旧版，回滚需要它）
Copy-Item "${letter}:\EFI\BOOT\BOOTx64.efi" 'E:\OC_SH\backup\2026-11-22-oc-before-1.0.8-debug\BOOTx64.efi'

# 3) 部署 EFI\OC（排除文档/备份/esp 暂存区）
robocopy 'E:\OC_SH' $esp /E /XD .git docs backup esp /XF README.md changelog.md /R:1 /W:1 /NFL /NDL

# 4) 部署 EFI\BOOT（只有 BOOTx64.efi）
robocopy 'E:\OC_SH\esp' "${letter}:\EFI" /E /R:1 /W:1 /NFL /NDL

if ($LASTEXITCODE -ge 8) { throw "robocopy failed: $LASTEXITCODE" }
```

## 6. 卡住之后怎么取日志

1. 复现：重跑更新，等进度条卡住；
2. **先拍照**屏幕最后几行（`-v` 的内核输出和 OC 日志文件可能互补）；
3. 强制关机，进 Windows；
4. 挂 ESP，拷出日志：

```powershell
# 提升权限；$letter 为 ESP 盘符
Get-ChildItem "${letter}:\" -Filter 'opencore-*.txt' | Sort-Object LastWriteTime | Select-Object -Last 3
Get-ChildItem "${letter}:\" -Filter 'panic-*.txt'
# 拷最新的那份回仓库
```

5. 判读：

| 现象 | 日志域 |
|---|---|
| 选择界面之后就黑屏/无文字，进度条一直不动 | OpenCore/固件侧 → 看 `opencore-*.txt` 尾部 |
| 有 `-v` 文字，滚到某行停住 | 内核侧 → 最后一行通常点名 kext/驱动 |
| 直接重启无输出 | 看 `panic-*.txt`（`ApplePanic` + `keepsyms=1` 才有符号） |

ESP 只剩 ~167 MB，调试完把日志删掉。

## 7. 风险与未决项

- **旧版本号没有确认**：`OpenCore.efi` 里读不出版本字符串，旧 config 的 schema 早于 1.0.8，无法反推具体版本。这导致「回退到原版本 DEBUG」这条路没有直接解——真要回退只能整包退回 RELEASE。
- **两个变量同时改了**（OC 版本 + 调试开关）。如果 1.0.8 起不来，先按 `backup/…/README.md` 回滚二进制和 config，再单独谈日志，别同时排查。
- **DEBUG + `-v` 会明显拖慢开机**，且每次引导都写一个日志文件。排障结束要回滚（见 §8）。
- `apfs_aligned.efi` 是自制件，OC 1.0.8 的驱动模型对它只是「兼容即加载」，没有版本保证。
- **旧的 `EFI\Boot\bootx64.efi` 来源不明**：3,086,728 B（2026-07-26），PE32+ 但 ASCII/UTF-16 里搜不到 `OpenCore`/`Clover`/`rEFInd` 任何标识，不是官方那套 ~53 KB 的启动器。已原样备份成 `backup/…/esp-BOOTx64.efi`。如果换完 EFI 后**连 OC 选择界面都不出现**，第一个要怀疑的就是这个文件 —— 回滚时它和 `OpenCore.efi` 要一起换回，别只换一个。

## 9. 本次踩到的坑（下次别再踩）

### 9.1 Windows PowerShell 5.1 + UTF-8 无 BOM + 中文注释 = 脚本后半段被吃

写一个带中文注释的 `.ps1`、存成 UTF-8 **无 BOM**，用 `powershell -File` 跑，5.1 会按 ANSI(GBK) 解码，中文注释所在行会把紧随其后的赋值语句吞掉。实测现象极具误导性：

```
$bk = 'E:\OC_SH\backup\...'          # 这行“执行了”，但 $bk 是 $null
W "bk=[$bk]"                          # 输出 bk=[]
New-Item -Path $bk                    # Cannot bind argument to parameter 'Path' because it is null
```

最小复现：同样的三行，加一行中文注释 → 失败；去掉注释或给文件加 BOM → 正常。

**结论：凡是给人看的脚本（含中文注释/字符串），一律写 UTF-8 with BOM**，或者用 PowerShell 7 (`pwsh`)。本仓库所有 `.ps1` 示例都按这个约定。

### 9.2 提权会话不继承盘符，`mountvol` 输出还会随语言变

`mountvol` 在提权会话里输出的是本地化文本（本机是 `EFI 系统分区装载在 D:\`），拿英文 `The EFI System Partition is mounted at` 去匹配必然失败；而且盘符是 **per-session** 的，非提权会话看到的 `D:` 提权会话未必有。

可靠做法（按顺序）：

1. `Get-Partition | Where GptType -eq '{c12a7328-f81f-11d2-ba4b-00a0c93ec93b}'` 取 ESP 分区的 `DriveLetter`（与语言无关）；
2. 退而求其次用 `(?:mounted at|装载在)\s+([A-Z]):` 双语正则；
3. 都没有再 `mountvol <字母>: /S` 现挂一个空字母。

### 9.3 部署脚本不能顺手 `/MIR`

ESP 上有 macOS 侧的文件（`EFI\APPLE\*`、`.DS_Store`、`._*`）和仓库里没有的东西。`/MIR` 一跑就可能删掉开机的关键件。本次只用 `/E`（只增改）+ `/XD docs backup esp` + `/XF` 排除仓库资料，部署后 ESP 文件数 381 → 381，没多也没少。
